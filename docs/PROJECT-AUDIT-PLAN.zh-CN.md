## 不可突破的边界

- 不对生产 Zammad 执行创建、更新、删除、回复、分配、上传或测试 webhook。
- 不在生产或共享 PostgreSQL 执行迁移、`db push`、seed、清理或真实集成测试。
- 所有自动化验证默认使用 mock、不可连接占位地址或命名明确的独立测试环境。
- 保留用户现有未提交修改；不使用破坏性 Git 命令，不顺手重构未经验证的生产路径。
- 高风险修改先给出证据、影响面、回滚方式和验证方案，再实施。

## 执行顺序

1. **基线与工具链**：核对 Git 状态、Node/Next/React/TypeScript/Prisma 版本、脚本、CI、环境变量和构建警告；评估 TypeScript Go 原生预览版时只比较类型检查/构建耗时，不宣称提升应用运行性能。
2. **安全与权限**：审查认证回退、RBAC、管理员 API、`X-On-Behalf-Of`、webhook 签名、文件上传/下载、日志与密钥暴露、开发入口和输入校验。
3. **数据与 Zammad 边界**：核对 Prisma schema、迁移一致性、事务/补偿逻辑、幂等性、超时重试、分页过滤、用户与工单映射、service-group 分配和生产故障降级。
4. **可靠性与实时链路**：审查 webhook → `TicketUpdate` → SSE → polling fallback、连接清理、并发、重复事件、跨实例部署、内存增长和可观测性。
5. **测试与 CI**：区分纯单元、mock 集成、数据库集成和 E2E；优先补齐高风险路径并逐步提高 CI 覆盖率基线至目标，治理脆弱测试、误导日志、测试数据隔离和 artifact。
6. **前端质量**：检查三端关键流程、错误/空/加载状态、可访问性、移动端、缓存一致性、国际化完整性与真实硬编码；避免无业务收益的视觉重写。
7. **性能与依赖**：用测量结果处理构建追踪、bundle、数据库/Zammad 请求放大、缓存和依赖安全；升级必须单独验证兼容性与回滚。
8. **运维与文档**：核对启动、健康检查、部署、备份恢复、告警、日志保留和灾难恢复；让文档反映当前代码，而非历史设想。

## 每阶段工作方式

- 先用 `rg`或者其它工具，哪个顺手你用哪个、直接文件读取和可复现命令收集证据，再下结论。
- 按 `P0`（立即风险）、`P1`（高风险）、`P2`（重要债务）、`P3`（优化）记录问题，附文件/行号、触发条件、影响和验证缺口。
- 小而低风险的问题可连同回归测试直接修复；架构、数据迁移、生产集成和大依赖升级先提交决策说明。
- 每批修改后执行最小相关测试，再执行 lint、类型检查、完整 Vitest 和隔离构建；E2E 仅在隔离环境可证明时运行。

## 交付标准

- 问题清单有证据、优先级和明确结论，不把猜测写成事实。
- 修复包含回归测试或说明无法自动验证的原因。
- 记录实际命令、结果、未执行项和生产隔离方式。
- 文档、CI 与代码行为一致；无真实密钥、客户数据或意外生成文件进入差异。
- 最终给出：已修复项、剩余风险、建议顺序、是否可发布，以及需要人工/隔离环境验证的事项。
