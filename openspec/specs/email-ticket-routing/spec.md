# 邮件抄送展示与初始分配

## Requirement: 邮件元数据展示
系统 MUST 在管理员和技术支持的工单消息中按邮件展示原始 CC 字符串；空值隐藏，姓名与地址按文本渲染，多人抄送可换行。

### Scenario: 邮件线程的抄送变化
- GIVEN 同一工单有两封带不同 CC 的邮件
- WHEN 管理员或技术支持查看消息
- THEN 每封邮件展示自身 CC，后续回复不修改负责人

## Requirement: 客户服务分组确定区域，唯一可用 CC 坐席优先承接新邮件
系统 MUST 仅在未分配、new/open、待分配区工单的首封公开客户邮件回调中使用 CC 分配。系统 MUST 从 Zammad 读取首篇文章，而非仅信任 webhook 中的 CC。客户服务分组确定区域；开启 CC 自动分配时，同区域 full 权限、active Agent、非管理员/系统账号且未休假的唯一邮箱匹配者优先于固定负责人。邮箱去重、忽略大小写，不以显示名或别名猜测身份。若 CC 含空收件项或无法完整解析的格式（如引号外注释或地址组），系统 MUST 对整个列表回退，不可根据残缺名单自动选择坐席。

### Scenario: CC 与固定负责人不同
- GIVEN CC 自动分配已开启，客户已有服务分组，首封邮件抄送唯一符合条件的另一位坐席
- WHEN 新邮件工单路由
- THEN 工单分给该坐席，区域与客户长期服务分组不变

### Scenario: CC 无匹配或多人可承接
- GIVEN CC 为空、无符合条件的匹配或有多名符合条件的匹配
- WHEN 新邮件工单路由
- THEN 使用服务分组固定负责人；固定负责人也不可用时保留待处理并通知管理员

### Scenario: 客户尚无服务分组
- GIVEN 客户没有服务分组，即使 CC 存在有效坐席
- WHEN 新邮件工单路由
- THEN 保留待处理并通知管理员，不根据 CC 推断客户区域

## Requirement: 独立启用与回退
系统 MUST 仅在 `EMAIL_CC_AUTO_ASSIGN_ENABLED` 明确为 `true` 时启用 CC 初始分配，未设置或其他值时使用服务分组负责人；该开关 MUST NOT 隐藏邮件 CC 或重新分配历史工单。实际部署环境变量变更通过重启应用进程生效。

### Scenario: 关闭 CC 自动分配
- GIVEN 首封邮件抄送唯一合格技术支持，但开关未开启
- WHEN 邮件路由
- THEN 不查询 CC 候选，使用服务分组固定负责人；工单详情仍显示抄送信息

### Scenario: 首封邮件创建时间相差超过 5 秒
- GIVEN 未分配的待处理区工单首封公开客户邮件与工单创建时间相差超过 5 秒
- WHEN 收到该邮件的 webhook
- THEN 仍按原始首篇文章与当前开关判定初始负责人，不因时间差跳过路由

## Requirement: 与其他分配入口协调
CC MUST 只决定初始分配；系统 MUST 在执行前重读工单，跳过已经分配、离开待分配区、进入其他状态或客户/负责人变更标记发生变化的工单，并以一次更新写入区域、负责人和状态。切换开关开启时暂停路由。系统 MUST NOT 因更新超时就盲目回滚。

### Scenario: 已完成回调重放
- GIVEN 工单已经按 CC 分配
- WHEN 原始 webhook 再次到达或批量自动分配运行
- THEN 已分配工单被跳过，不按服务分组负责人覆盖

### Scenario: 管理员后续主动操作
- GIVEN 工单由 CC 坐席负责
- WHEN 管理员明确改派或迁移客户服务分组的未关闭工单
- THEN 管理员操作继续生效，后续邮件不会恢复 CC 初始负责人

### Scenario: 解析期间发生人工改派
- GIVEN 原始 webhook 尚在查询收件人
- WHEN 最后一次读取发现工单已经改派或迁移
- THEN 取消本次自动写入

此规格不声明跨实例或外部管理操作的强事务互斥。Zammad REST 更新未提供条件式 owner 比较；最后读取与写入之间的并发操作仍以实际写入顺序为准。

## Requirement: 技术失败可重试
系统 MUST 将完成路由所必需的依赖读取失败（包括暂时未返回首篇文章）与明确的业务不可分配结果区分。必要依赖读取或更新失败时返回可重试结果，Webhook MUST 返回 HTTP 503，并尽力通知管理员；重试 MUST 重新读取当前工单，避免重复写入已经成功的分配。CC 候选查询失败仍按既有策略回退固定负责人；固定负责人无法读取时才返回可重试结果。

### Scenario: 首封文章短暂不可读取
- GIVEN 首封客户邮件回调到达，但 Zammad 文章 API 暂时失败
- WHEN 本次 webhook 处理结束
- THEN 返回 503 而不是成功，保持未分配状态并尽力通知管理员；本次失败尝试不写入 TicketUpdate、不广播 SSE、不产生普通事件通知
- WHEN 原始 webhook 在依赖恢复后重试
- THEN 正常执行初始分配，成功回调再次重放不重复写入

### Scenario: 更新成功但响应丢失
- GIVEN Zammad 已完成更新，但应用收到失败响应或超时
- WHEN webhook 重试
- THEN 读取当前负责人并跳过已完成分配，不盲目回滚或再次写入

### Scenario: 带组名的抄送地址
- GIVEN CC 为 `Support: first@example.com, second@example.com;`
- WHEN 当前保守解析器无法完整解析地址组
- THEN 整体使用固定负责人回退，不丢弃第一项后误判第二项为唯一匹配
